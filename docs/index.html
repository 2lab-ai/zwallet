03 / Keep control

Rules checked
outside the prompt.

The signing process decodes the requested transaction and checks the policy itself. An agent calling it an “allowed payment” is not enough.

  • Recipients and limits per transactionCheck allowed payees, EVM selectors and configured amount and fee limits.
  • Human unlock. Time-limited access.The person enters the password. When the session expires, new signing ends.
  • Lock whenever you need to.Lock ends every zwallet signing session for your OS user.

Per-payment limits are not cumulative budgets. Repeated permitted payments can spend the balance, and same-user processes share the access boundary. Lock does not reverse transactions already sent. Read the security model ↗

Before you begin

A few useful answers.

Do I need an account or a special token?

No zwallet service account or dedicated token is required. You still need funds, native gas and RPC access for the network you choose.

Which agents can use it?

Agents that can run the local CLI and read JSON results can use it. The person sets up the wallet and policy first. The diagram explains the workflow; it is not a shipped dashboard.

Is the allocation a hard task budget?

Today, the allocation is the balance you put in a dedicated wallet. Limits per transaction are available; enforced task and daily budgets are WIP. Repeated permitted payments can spend the full balance.

Can it invest or shop for me today?

There is no built-in investment strategy, merchant checkout or service-payment adapter today. zwallet is the wallet component; these workflows are WIP. Investing can result in losses.
